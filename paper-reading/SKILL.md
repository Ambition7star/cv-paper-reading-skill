# Paper Reading — CV 科研论文深度精读与写作拆解

## Overview

本 skill 把一个"顶会级"论文阅读流程固化为固定执行规范：从零到一完整精读一篇计算机视觉/AI 论文（方法、公式、图表、实验、消融、证据边界），再单独做论文逻辑框架与科研写作分析，最后落到可复现的实验计划和 RGB-T 方向迁移启发。适用于研究者、研究生，特别是做多模态目标检测（RGB-T/RGBT）、Mamba 架构、低空无人机场景的用户。

除非用户明确修改要求，否则必须完整执行本流程，不能缩减、拆分或省略。

## Workflow Decision Tree

- **用户给了一篇论文要求精读** → 进入 [PART 1：从零到一完整精读](references/part1-deep-reading.md)
- **用户要求分析论文如何设计/写作/叙事** → 进入 [PART 2：论文逻辑框架与科研写作分析](references/part2-writing-analysis.md)
- **两个都要** → 先 PART 1 完整精读，再 PART 2 写作分析
- **用户只想快速了解 / 没说是深度精读** → 先问清楚是否要走完整流程，不要擅自跳过
- **用户要求结合代码 / GitHub / 博客** → 才允许引入源码与二手解读；否则一律只用论文正文

## 基本原则（所有情况适用）

1. **只依据论文正文**：默认不结合源代码、GitHub README、博客或其他二手解读。只有用户明确说"结合代码"时才分析源码。
2. **从零讲解**：假设用户对论文涉及的领域、模型和公式基础不足，专业但必须通俗易懂。
3. **一次性完整输出**：不要拆成多轮，不要讲到一半询问是否继续，不要设置理解检测或让用户选择下一部分。
4. **不因内容多而缩减篇幅**：优先保证完整性、细节、深度和逻辑连贯性。
5. **三层区分**：必须区分「论文明确表述的内容」「根据论文合理推导的内容」「你自己的批判性判断」。
6. **不复述宣传语**：结合公式、图表、实验和消融，判断论文实际证明了什么、没证明什么。
7. **正文先在聊天框输出**：所有正文必须先直接输出在聊天框中，方便用户连续阅读；不能只生成文件或只发下载链接。

## 输出契约（最终交付）

1. 先在聊天框中一次性完整输出 PART 1 和 PART 2 全部内容（若都要求）。
2. 不得只提供摘要、目录、提纲或文件链接。
3. 聊天框正文完成后，再生成两份独立 Markdown，且必须包含聊天框中的完整内容，不能是缩减版：
   - `论文名_完整精读与实验假设.md`（PART 1）
   - `论文名_论文逻辑框架与科研写作分析.md`（PART 2）
4. 不要中途询问是否继续，也不要因为输出较长自行删减。
